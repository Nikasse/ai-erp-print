# AI Assistant Notes — Урок 11

Документація AI-помічника у фінансовій адмінці.

## 1. Що побудовано

AI-помічник у вигляді чату всередині фінансової адмінки.

Ланцюг: React AI Chat → Backend (`POST /api/ai/chat`) → LangGraph-агент
→ read-only tools → Neon DB → відповідь.

Побудовано на LangGraph (`create_react_agent` + `MemorySaver`), модель
`claude-haiku-4-5` через `ChatAnthropic` (`app/agent.py`).

## 2. Пам'ять (short-term memory)

`thread_id` зв'язує повідомлення в один діалог. Backend створює
`thread_id` через `uuid4()` при першому повідомленні (коли фронтенд
шле `thread_id: null`) і повертає його у відповіді. Фронтенд зберігає
цей id і шле той самий у наступних запитах.

LangGraph `MemorySaver` (checkpointer) зберігає контекст діалогу за
ключем `thread_id`. Перевірено в UI: на репліку "за весь" (без
уточнення періоду) агент зрозумів, що йдеться про період з
попереднього питання — контекст підтягнувся коректно.

## 3. Tools (read-only)

Три дозволені функції в `app/tools.py`:

- `get_transactions_summary(period)`
- `get_category_totals(period)`
- `get_top_expenses(period, limit)`

Модель НЕ пише SQL сама, НЕ має доступу до write-операцій і `.env`.
Вона тільки викликає ці три функції. Принцип: контрольований доступ
через дозволені двері, а не прямий доступ до бази.

## 4. Чому tools тільки читають

На цьому етапі помічник лише аналізує. Write-операції (додати,
видалити, змінити операцію) потребували б окремого підтвердження
користувача, перевірки прав, валідації та логування — тому їх нема.

## 5. Безпека і логування

- system prompt українською, забороняє вигадувати суми/категорії,
  вимагає чесно казати, якщо даних мало;
- кожен tool call логується: назва tool + параметри, але НЕ повний
  результат і НЕ секрети;
- React звертається тільки до нашого backend, ключ живе лише на
  backend;
- кнопка блокується під час loading, паралельні запити не йдуть.

## 6. Що далі

Технічний борг:

- пул з'єднань для Neon;
- write-tools з підтвердженням (майбутній етап);
- persistent memory замість short-term (зараз контекст живе в
  пам'яті процесу і губиться при перезапуску backend).
