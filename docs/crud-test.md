# Урок 8: CRUD-адмінка — керування операціями

Дата: 20 липня 2026.
Гілка: `lesson-8/crud`.

## Що додано

Адмінка з Уроку 7 (тільки перегляд) перетворена на повноцінну
адмінку керування: тепер можна додавати, видаляти й фільтрувати операції.

### Backend (app/api.py)

- **POST /api/transactions** — створення операції.
  Схема входу `TransactionIn`: amount, type (income/expense), category, description.
  Валідація на бекенді (HTTP 400 при помилці):
  - amount має бути більше 0;
  - type має бути income або expense;
  - category не порожня.
- **DELETE /api/transactions/{id}** — видалення операції.
  HTTP 404, якщо операції з таким id немає.

### Frontend (admin/src/App.jsx)

- **Форма додавання** — поля сума / тип / категорія / опис, кнопка "Додати".
  POST на API, після успіху оновлює таблицю й картки (fetchTransactions + fetchSummary).
  Показує помилку бекенду (поле detail), якщо валідація не пройшла.
- **Кнопка "Видалити"** у кожному рядку — з підтвердженням через window.confirm.
  Cancel — операція лишається; OK — DELETE-запит, потім оновлення таблиці й карток.
- **Фільтри** "Усі / Доходи / Витрати" — змінюють, які рядки показані.
  Фільтрація локальна (за type), без запитів до бази. Дані не видаляються.

## End-to-end перевірка (пройдена руками)

- POST через curl: amount=500, income, "Продаж" -> операція створена (id повернувся).
- Валідація: amount=0 -> 400 "amount має бути більше 0";
  type="донат" -> 400 "type має бути 'income' або 'expense'".
- DELETE через curl: видалення працює, повторне видалення -> 404 "Операцію не знайдено".
- Форма в браузері: додавання операції -> зʼявляється в таблиці, картки оновлюються.
- Кнопка "Видалити": OK прибирає рядок і перераховує баланс; Cancel лишає рядок.
- Фільтри: "Доходи" показує тільки income, "Витрати" тільки expense, "Усі" — все.
  Перемикання не видаляє дані.

## Безпека

- React не містить DATABASE_URL, BOT_TOKEN чи інших секретів.
- Секрети лишаються у .env (не в git).
- Фронтенд працює тільки через backend API, напряму до бази не звертається.

## Відомі обмеження (на майбутнє)

- Neon присипляє базу після паузи: перший запит може впасти з
  connection is closed, повторний прокидається. Для продакшену — пул зʼєднань.
- Форма не блокує повторний клік під час запиту (можна двічі додати ту саму операцію).
- Підтвердження видалення — через window.confirm (у продакшені — модальне вікно).
