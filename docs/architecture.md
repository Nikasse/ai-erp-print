# Архітектура продукту

Опис IT-продукту як системи блоків, а не набору випадкових файлів.
Приклад — наш Telegram-бот на aiogram (проєкт `ai-erp-print`).

---

## Продукт — це не один файл

IT-продукт складається з блоків, які працюють разом. Кожен блок робить своє:

- **Frontend (інтерфейс)** — показує
- **Backend (логіка)** — думає
- **Database (база даних)** — пам'ятає
- **API** — з'єднує
- **AI-модель** — додає інтелект (окремий блок, підключається за потреби)

Маршрут дії користувача:

```
Користувач → Frontend → API → Backend → Database → відповідь назад
```

---

## Блоки на прикладі нашого Telegram-бота

### Frontend — що бачить користувач
Інтерфейс, через який користувач взаємодіє з продуктом: бачить інформацію, вводить дані,
натискає кнопки, отримує результат.

- **У веб-SaaS:** сайт або веб-додаток.
- **У нашому боті:** сам **Telegram** — вікно чату, кнопки, команди `/start`, `/help`.

### API — канал взаємодії
Правила, за якими різні частини продукту обмінюються запитами й відповідями. Передає запити,
отримує відповіді, відокремлює frontend від backend.

- **У нашому боті:** **Telegram Bot API** — через нього повідомлення від користувача доходять
  до нашого коду, а відповіді — назад у чат.

### Backend — логіка
Обробляє дію: перевіряє, рахує, вирішує, що робити. Це «мозок» продукту.

- **У нашому боті:** **aiogram-застосунок** (`app/main.py`) — приймає команду, вирішує, що
  відповісти (`handle_start`, `handle_help`), і віддає результат назад через API.

### Database — пам'ять продукту
Місце, де продукт зберігає інформацію, щоб не «забувати» користувача і його дії. Без бази
продукт пам'ятає лише поточну дію; з базою — має історію.

- **У нашому боті:** поки що **бази нема** — бот відповідає на команди, але нічого не зберігає
  між запусками. Це наступний важливий блок для розвитку (напр. зберігати користувачів,
  історію команд, налаштування).

### AI-модель — інтелект
Окремий блок системи, до якого backend може звертатися через API: пояснити, класифікувати,
створити звіт, знайти аномалії, дати рекомендації.

- **У нашому боті:** поки не використовується. У майбутньому backend зможе слати запит до AI
  і показувати користувачу відповідь.

Маршрут з AI:
```
Backend бере дані → надсилає запит до AI → отримує відповідь → показує користувачу
```

## Розбір функцій знайомих застосунків через блоки

Одна дія користувача проходить через кілька блоків системи. Розкладемо реальні функції:

### 1. Банківський застосунок — «переглянути баланс»
| Блок | Що робить |
|---|---|
| Frontend | користувач тисне «Баланс» у застосунку |
| API | передає запит на backend |
| Backend | рахує баланс = доходи − витрати |
| Database | зберігає всі операції (доходи + витрати) |
→ Backend бере операції з бази, рахує підсумок, frontend показує число.

### 2. Telegram-бот — «додати витрату»
| Блок | Що робить |
|---|---|
| Frontend | користувач вводить суму в Telegram |
| API | передає повідомлення на backend |
| Backend | перевіряє суму, категорію, користувача |
| Database | зберігає нову операцію |
→ Одна проста дія = кілька блоків системи.

### 3. Notion / Trello — «створити картку»
| Блок | Що робить |
|---|---|
| Frontend | користувач натискає «+ Нова картка», вводить текст |
| API | відправляє дані на сервер |
| Backend | перевіряє права доступу, формує запис |
| Database | зберігає картку (текст, список, автор, дата) |
→ Картка з'являється в усіх, хто має доступ — бо вона в базі, а не в браузері.

### 4. ChatGPT — «поставити запитання»
| Блок | Що робить |
|---|---|
| Frontend | користувач пише запит у вікно чату |
| API | передає запит на backend |
| Backend | готує контекст, звертається до AI-моделі |
| AI-модель | генерує відповідь |
| Database | зберігає історію діалогу |
→ Тут AI-модель — окремий блок, до якого backend іде через API.

### 5. Сервіс фінансового обліку — «звіт за місяць»
| Блок | Що робить |
|---|---|
| Frontend | користувач обирає місяць, тисне «Звіт» |
| API | передає запит |
| Backend | вибирає операції за період, групує по категоріях |
| Database | зберігає всі операції |
| AI-модель | (опційно) пояснює витрати, дає рекомендації |
→ Backend збирає дані з бази, рахує, за потреби питає AI, frontend показує звіт.

## Головний висновок

Продукт — це **система блоків**, а не купа файлів. Розуміння, де frontend, де backend, де база
й де проходить API, дозволяє:
- знати, **куди** додавати нову функцію;
- давати AI **точні** задачі («додай backend-логіку для підрахунку з бази»), а не «зроби все»;
- бачити, **який блок** змінився при помилці.
