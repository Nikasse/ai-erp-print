# End-to-end перевірка: Telegram → Neon → Admin

Дата перевірки: 18 липня 2026.
Гілка: `saas/admin-dashboard`.

## Мета

Переконатися, що дані проходять весь ланцюг наскрізь — від повідомлення
в Telegram до відображення у web-адмінці — без ручного втручання між ланками.

## Ланцюг даних

```
Telegram (/expense)
  → aiogram backend приймає команду
  → запис у Neon Postgres (type=expense, категорія "Витрати")
  → FastAPI читає з бази (GET /api/transactions, GET /api/summary)
  → React-адмінка отримує дані через API
  → таблиця показує рядок, картки перераховують суми
```

## Сценарій перевірки

1. У Telegram надіслано боту команду: `/expense 250 обід`
2. Бот відповів, що витрату збережено.
3. В адмінці (`localhost:5173`) оновлено сторінку.
4. Результат:
   - у таблиці зʼявився новий рядок: дата `2026-07-18`, тип `expense`,
     сума `250`, категорія «Витрати», опис «обід»;
   - картки ожили: Витрати `250`, Баланс `-250`.

## Що це підтверджує

- Бот коректно пише в базу з правильними `type` і `category`
  (дефолтна категорія «Витрати» для `/expense`).
- Endpoint `/api/transactions` віддає список операцій.
- Endpoint `/api/summary` рахує доходи/витрати/баланс за полем `type`.
- React читає дані **тільки через backend API**, а не напряму з бази.

## Відомі обмеження (на майбутнє)

- Neon присипляє базу після паузи: перший запит може впасти з
  `connection is closed`, повторний — прокидається. Для продакшену
  потрібен пул зʼєднань, що вміє перепідключатися.
- Адмінка оновлюється лише при перезавантаженні сторінки
  (fetch на mount). Автооновлення — тема наступного уроку.
- Старі записи без `type`/`category` не враховуються у summary
  (це очікувано — вони створені до додавання дефолтної категорії).
